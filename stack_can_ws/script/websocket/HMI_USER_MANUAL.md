# 车辆键盘控制用户手册

适用脚本：`hmi_keyboard_client.py`，包含原点标定（5）与漂移计算（y）的版本。

## 1. 使用前准备

确认车辆周围具备安全操作空间，急停装置可用，RTK、雷达、超声波及CAN状态正常。定位标定必须在车辆物理停稳后进行；软件发送暂停并不代表车辆已经停稳。

本手册对应的新标定功能已更新到Jetson文件，但部署时未重启导航。首次使用前需在安全停机状态重启导航，使新服务端及补偿节点生效。只重新打开键盘客户端不能加载新的服务端逻辑。

原点是用于测量定位偏移的固定参考点，不是路径起点，也不会修改路径坐标。首次参考基准应与路径采集时的定位基准一致。

## 2. 启动与状态检查

先按设备现有流程启动导航主程序。手动启动入口为：

```bash

```

如导航服务已经运行，无需再次执行入口脚本。

在Jetson另一个交互终端中运行：

```bash

```

在电脑上运行客户端时，将主机地址改为Jetson地址：


看到控制连接和状态连接后，检查设备状态及外设错误。状态异常时先处理故障，再进行行驶操作。完整控制模式连接时不会自动发送运行指令，也不会自动切换为手动控制。

## 3. 定位标定与漂移补偿

### 3.1 标定或重新定义参考原点：按5

1. 将车辆停在选定的固定参考位置，记录车辆位置和朝向，便于后续准确复位。
2. 确认车辆已物理停稳、定位输出正常。
3. 按一次 `5`。系统发送暂停和遥控清零指令，等待约2秒后开始采样。
4. 保持车辆静止至少5秒，等待终端返回“原点已覆盖，旧补偿已清零”。
5. 完成后车辆保持暂停，不会自动开始循迹。

每次按5并成功完成采样，都会覆盖原点记录。采样不足、定位波动过大或超时会返回失败，不能把开始采样提示当成完成提示。

重新标定原点会改变定位参考基准；使用已有路径前，需要确认新基准与路径采集基准一致。

### 3.2 回到原点计算漂移：按y

1. 将车辆停回原点标定时的同一物理位置，尽量保持相同朝向。
2. 确认车辆已物理停稳。
3. 按一次 `y`，保持静止，等待约2秒准备和5秒采样完成。
4. 确认终端返回“漂移量已更新，原点不变”。
5. 根据作业需要选择循迹，再手动按 `g` 开始。

该操作只更新漂移补偿，不覆盖原点。没有原点记录时会提示先标定原点，不会自动创建原点。

### 3.3 两个按键的区别

| 按键 | 使用时机 | 原点记录 | 漂移补偿 |
|---|---|---|---|
| 5 | 首次建立或明确重新定义参考点 | 覆盖 | 清零 |
| y | 回到既有参考点后修正定位偏移 | 保留 | 重新计算并覆盖 |

原点和补偿量均持久保存，重启后继续使用。正常启动不要求车辆停在参考点；只有按y重新计算漂移时，才必须回到参考点。尚未建立原点时使用零补偿。

补偿原理：漂移量=本次参考点平均定位−原点坐标；修正定位=实时定位−漂移量。循迹和电子围栏统一使用修正位置。补偿仅针对水平平移，不修正航向，也不会自动跟踪后续变化的漂移。

## 4. 自动循迹操作

1. 确认路径文件、电子围栏和定位状态正确。
2. 如需更新漂移，先按第3.2节完成操作。
3. 按 `n` 重载路径并选择循迹，等待成功回执。
4. 确认环境允许车辆运动后，按 `g` 开始循迹。
5. 需要暂停时按 `z`；异常时按 `x` 急停。
6. 任务点作业完成后，如流程需要人工确认，按 `f` 通知任务完成。

`u`用于选择自动控制，`t`用于切换遥控与循迹；切换到循迹后保持暂停。选择模式、加载路径与开始运行是不同操作，需结合终端回执和实际车辆状态判断。

## 5. 手动遥控

按 `m` 请求手动接管；确认控制模式、速度与转角均符合预期后，按 `g` 请求运行，再使用速度和转向键。

| 按键 | 操作 |
|---|---|
| w 或 4 | 前进4 km/h |
| 8 | 前进8 km/h |
| s 或 1 | 后退4 km/h |
| 0 | 速度归零，转角保留 |
| a / d | 左转10° / 右转10° |
| q / e | 左转20° / 右转20° |
| c 或空格 | 速度、转角归零 |
| z | 暂停 |
| x | 急停 |
| r | 请求安全复位，保持暂停 |

速度和转角是持续设定值，松开按键不会自动停车。按转向键时原速度会保留；按速度键时原转角会保留。完整模式下空格不会清除作业开关。普通行驶指令没有成功回执，“已发送”不等于“已执行”。

## 6. 作业控制

| 按键 | 功能 |
|---|---|
| j | 切换倾倒开关 |
| k | 切换捡拾开关 |
| l | 切换卸载开关 |
| h | 切换捡拾动作开关 |

j和k互斥，打开其中一个会关闭另一个。h打开时会关闭捡拾、倾倒；h保持打开期间不能用j/k切换，须先按h关闭。作业位保持到再次切换或相关复位操作。

仅测试倾倒和捡拾时，可使用默认的受限模式：

```bash
python3 hmi_keyboard_client.py --host 127.0.0.1 --work-only
```

此模式连接后会请求暂停、全零指令、手动接管；屏蔽行驶、标定等按键，允许j/k、r、c/空格、x及维护操作。c/空格会清除所有作业位。暂停状态下是否执行作业，取决于VCU逻辑。

## 7. 其他功能

| 按键 | 功能与操作说明 |
|---|---|
| v / b / p | 开启相机 / 关闭相机 / 查询相机 |
| o | 查询CAN底层状态 |
| i | 请求恢复CAN；按下即表示确认车辆已停止，恢复后保持暂停 |
| ! | 3秒内按两次请求重启导航；操作前必须停稳，其他按键取消首次确认 |
| 9 | 查询导航重启任务 |
| ? | 显示当前模式帮助 |
| Esc / Ctrl+C | 退出客户端 |

重启请求后，客户端限制普通操作。请结合9011状态中的新boot_id确认导航确实重启，不能只凭接受回执判断完成。

## 8. 状态查看与文件上传

只查看状态，不连接控制端口：

```bash
python3 hmi_keyboard_client.py --host 127.0.0.1 --status-only
```

查看完整状态信息：

```bash
python3 hmi_keyboard_client.py --host 127.0.0.1 --status-only --verbose
```

上传路径或围栏CSV，收到`saved:`才表示上传成功：

```bash
python3 hmi_keyboard_client.py --host 127.0.0.1 --upload-points /实际路径/points.csv
python3 hmi_keyboard_client.py --host 127.0.0.1 --upload-fence /实际路径/fence.csv
```

上传路径后不会自动开始循迹，应按n重载并确认结果，再按g开始。围栏上传后的加载时机需结合主程序实际行为确认。

离线查看按键生成的指令，不连接设备：

```bash
python3 hmi_keyboard_client.py --full-control --dry-run --keys 5y
```

## 9. 暂停与退出

正常结束操作时先按z暂停，确认车辆停止，再退出客户端。客户端退出时会尽力发送一次全零遥控指令；控制连接断开后的停车保护由Jetson服务端执行，不能用关闭窗口代替确认停车。

状态连接断开后会自动重连；控制连接断开后不会自动重连或重发运动指令。恢复网络后重新启动客户端，检查状态后再操作。客户端每0.5秒发送一次心跳。

## 10. 常见问题

| 现象 | 处理方式 |
|---|---|
| 按5/y显示“已屏蔽” | 当前是work-only模式，重新以--full-control启动 |
| y提示尚未标定原点 | 先在固定参考位置按5标定 |
| 只有采样开始提示，没有成功提示 | 保持暂停，检查定位状态和最终回执；失败时不要假定补偿已更新 |
| 原点或漂移采样失败 | 检查是否停稳、RTK输出是否正常，再重新操作 |
| 按键已发送但车辆未动作 | 检查控制模式、RUN/PAUSE/急停状态及CAN/外设故障 |
| 5/y没有有效响应或超时 | 确认导航已重启加载新版本，检查补偿节点与9010服务端 |
| 控制连接断开 | 确认停车，恢复网络后重新运行客户端 |
